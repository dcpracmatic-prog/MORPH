# DIMACS MIS benchmark: measured results (2026-11-24)

41 DIMACS clique-benchmark graphs, run under two conventions, four budgets,
five seeds. This replaces the earlier 13-instance run (kept in
`superseded_13_instance_run/`, not to be cited as current).

## Protocol

- **Instances:** all 41 `.clq` files of the DIMACS Implementation Challenge
  clique set listed in `SOURCES.md`. Checksums: `SHA256SUMS.txt` (inputs as
  downloaded) and `SHA256SUMS_complement.txt` (generated complements).
- **Two conventions, reported side by side:**
  - **as-is:** MIS of the graph in the file.
  - **complement:** MIS of the complement of the file's graph. An independent
    set in the complement is a clique in the original, so this value is the
    clique number of the DIMACS graph and is the one comparable to published
    ω. Complements are written by `scripts/complement_dimacs.py`; every file's
    edge count was checked against n(n−1)/2 − m.
  - **Headline convention: complement.** Both are reported, and the complement
    values are the ones compared with ω below.
- **Solver:** `morph_qoblib_solver`, method `morph`, built from the
  branch source with `-O3 -std=c++17 -DNDEBUG`.
- **Budgets:** 10, 50, 100, 1000 ms. **Seeds:** 1–5.
- **Runs:** 41 instances × 5 seeds × 4 budgets × 2 conventions = **1640 runs**.
  Every run returned `valid=1`. That flag is the solver's own check on the
  graph it was given; this run did not re-verify the returned set with a
  separate checker.
- **Environment (measured in this sandbox):** Linux 6.1.189 x86_64 (Debian
  trixie, E2B VM), 2 vCPUs (`nproc`), g++ 14.2.0, Python 3.13.5. Runs were
  sequential with no other benchmark on the machine.
- **Runner:** `scripts/run_dimacs_mis.py --convention {as-is,complement}`.
  Per budget and convention it writes `dimacs_mis_runs.csv` (one row per
  run), `dimacs_mis_summary.csv` (per instance: mean, min, P10, P50, P90,
  max, wall-clock mean), and `DIMACS_MIS_REPORT.md`.
- **Combined view:** `combined_summary.csv` (long format) and
  `COMBINED_TABLE.md` (per instance, with ω), both generated by
  `scripts/dimacs_reference_table.py`.

## How to read the spread

With five seeds, [min, max] is the order-statistic interval for the median.
Under iid sampling it covers the population median with probability 1 − 2·(1/2)⁵
= 93.75%. Seeds are not a random sample of the solver's behaviour, so treat that
as an approximation. P10/P50/P90 are linear interpolations over the five values
and are descriptive, not confidence intervals.

## Results

Full per-instance table: `COMBINED_TABLE.md`. Each cell is P50 with [min–max]
over five seeds.

**Complement (clique) convention, 1000 ms:**

- 15 of the 35 instances with exact published ω reach ω on all five seeds:
  MANN_a9 (16), MANN_a27 (126), c-fat200-1/-2/-5 (12/24/58), c-fat500-1/-2/-5/-10
  (14/26/64/126), hamming8-4 (16), johnson16-2-4 (8), keller4 (11), keller5 (27),
  p_hat300-2 (25), p_hat500-1 (9).
- The gaps are large on some families. Examples (P50 vs ω): san200_0.9_1
  52 vs 70, san400_0.7_1 23 vs 40, san200_0.7_1 18 vs 30, brock400_4 23 vs 33,
  brock400_3 23 vs 31, san1000 10 vs 15, hamming10-4 36 vs 40, brock800_1 19 vs 23.
- On the five instances where the published value is only a lower bound, the
  P50 is below that bound on all five (complement, 1000 ms): p_hat1000-1 9 vs
  ≥10, p_hat1000-2 45 vs ≥46, p_hat1000-3 65 vs ≥68, p_hat500-3 49 vs ≥50,
  p_hat700-2 43 vs ≥44. That is a
  heuristic shortfall against a known solution, not a discovery. p_hat700-3 (62)
  matches its bound.
- No complement result exceeded an exact ω at any budget (checked by
  `scripts/dimacs_reference_table.py`).

**As-is convention:** MIS sizes are small on the dense DIMACS graphs (for
example brock200_1: 6, c-fat500-1: 40, p_hat300-1: 39). These numbers measure
a different quantity from clique number and are not compared with ω.

## What varies, and what does not

- **Budget:** a few complement results move with budget: keller5 25 at 10 ms
  and 27 from 1000 ms; p_hat1000-3 63 at 10 ms and 65 at 1000 ms; MANN_a45 343
  up to 100 ms and 344 at 1000 ms. Most instances are flat across budgets.
- **Seeds:** the number of instances with any seed spread is 13 at 10 ms and
  2 at 1000 ms for the complement convention, and 6 and 1 for as-is. A spread
  at 10 ms can disappear at 1000 ms.
- **Wall clock:** the budget is a deadline for starting restarts, not a hard
  cap. Mean wall time across the 41 instances and both conventions is 10.9 ms at
  a 10 ms budget (worst instance mean 17.0 ms, MANN_a45 as-is) and 101.0 ms at
  100 ms (worst 107.5 ms, p_hat1000-1 complement). Use the `wall_ms_mean` column, not the nominal budget.
- **Reproducibility:** the solver reads the wall clock, so budgeted runs are
  not bit-reproducible. Reruns on the 13 overlapping instances from the
  superseded run reproduced every P50 at 100 ms. One mean differed: p_hat300-1
  was 38.8 before and 39.0 now, a timing effect. Deterministic output is
  checked separately with a fixed-seed and fake-clock comparison, which is not
  part of this run.

## Limitations

- MORPH alone. No CP-SAT or other solver column for DIMACS, so this run makes
  no superiority claim.
- ω values come from a third-party table (roars.dev npbench clique page,
  fetched 2026-11-24, saved as `omega_reference.csv` with its source). They
  were not checked against the DIMACS originals.
- The solver's validity check is self-reported. This run did not verify
  returned sets with an independent checker.
- No optimality claim. Lower bounds in the reference table are marked `≥`.

## Reproduce

```bash
make all
# complements (needs the as-is files)
python scripts/complement_dimacs.py --in-dir /path/to/dimacs --out-dir /path/to/dimacs_complement
for conv in as-is complement; do
  dir=/path/to/dimacs; [ $conv = complement ] && dir=/path/to/dimacs_complement
  for b in 10 50 100 1000; do
    python scripts/run_dimacs_mis.py --dimacs-dir "$dir" --solver ./morph_qoblib_solver \
      --budget-ms $b --seeds 1,2,3,4,5 --convention $conv \
      --out evidence/dimacs_mis/$conv/budget_${b}ms
  done
done
python scripts/dimacs_reference_table.py
```

Verify inputs with `sha256sum -c SHA256SUMS.txt` in the instance directory. The
instance files are not vendored in this repository.
