## Convention

Both conventions are reported; complement is the headline (it is the clique number, comparable to ω).

- **as-is:** the `.clq` edge list is read unchanged and treated as an MIS instance.
  This matches the convention of the earlier PR and of the QOBLIB MIS run in this
  repository (see the QOBLIB note below).
- **complement:** each graph is replaced by its complement, so an independent set in
  the complement is a clique in the original. MIS on the complement is therefore the
  maximum clique of the original. The complement files are generated by
  `scripts/complement_dimacs.py` (edge count checked: each complement has
  n(n−1)/2 − m edges, 0 mismatches). SHA-256 of each complement:
  `SHA256SUMS_complement.txt`.

## Reference values (ω)

`omega_reference.csv` holds the maximum-clique values used for comparison: 35 exact
values and 6 lower bounds (marked `exact=0`). Source: the roars.dev npbench clique
table, fetched 2026-11-24 (`/home/user/work/roars_clique.html`, saved copy not in
the repository). This is a third-party table, not the DIMACS distribution itself.
Spot-checked against the saved HTML; not independently re-derived.

Comparison: `scripts/dimacs_reference_table.py` writes `combined_summary.csv` and
`COMBINED_TABLE.md`. It applies to the complement convention only, because the ω
values are clique numbers of the original graphs.

## QOBLIB mixed-convention finding

The earlier QOBLIB validation (`docs/RESULTS.md`) reported MORPH on QOBLIB MIS
instances, with reference values from the QOBLIB repository. The QOBLIB files were
not stored or re-read for this benchmark, so the following is an inference from
matching numbers, not a check of the QOBLIB files:

- `C125-9`: MORPH reached 34 on the QOBLIB run; `docs/RESULTS.md` calls 34 the
  official optimum. C125.9 is not in the DIMACS set used here, so the complement
  convention could not be checked on it in this benchmark.
- `brock200_1`: MORPH returned 6 on the QOBLIB run. The DIMACS as-is run gives 6 on
  the same graph. The complement run gives 20 (ω(brock200_1) = 21), so a complemented
  brock200_1 would not match the QOBLIB value. This points to the instance being used
  as-is in QOBLIB.

This is an inference from matching numbers. It is not a check of the QOBLIB files.
Verify against the QOBLIB files before relying on it.
